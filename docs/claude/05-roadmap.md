# 05 · 实施路线图

> 四个主要阶段；状态：提案，尚未实施验收。
> 最后整理：2026-10-13。历史调整见 [CHANGELOG.md](CHANGELOG.md)。

## 总览与当前下一步

| 阶段 | 任务 | 完成节点 |
|---|---|---|
| 1 | 数据与编辑基线，包含 PLY-only 基础编辑 | M1：选择、保护、删除、身份映射与导出可重复 |
| 2 | NativeBaseline 官方复现，随后验证 B2/B3 增强 | M2：官方修复基线成立，评测协议冻结 |
| 3 | 用户提示驱动的三维分离与 ExternalSelection 适配 | M3：外部选择到背景修复闭环通过验收 |
| 4 | 最小产品集成与按能力交付 | M4：对应能力的产品流程通过验收 |

**当前下一步**：选取一个有配准干净参考的公开场景和一个自有 Gaussian 场景；固定源资产身份及官方代码配置，同时启动阶段 1 的人工编辑和阶段 2 的 NativeBaseline。阶段 2 不等待自研编辑器输出。

五层模型用于诊断问题，不对应五个串行开发阶段。自动候选、完整光照处理和碰撞几何列在后续扩展，不占用主线阶段编号。

## 阶段 1 · 数据与编辑基线

### 目标

建立可检查、可撤销的人工编辑流程，尽早暴露资产身份与导出错误。PLY-only 的基础操作与完整数据的官方修复实验并行。

### 输入与前置条件

- 有效 Gaussian 资产、兼容查看器或渲染器；原始拍摄相机不是虚拟视角渲染的必要条件。
- 创建 SceneAsset，记录源哈希、版本、坐标约定和能力字段，见 [架构](04-architecture.md)。

### 步骤

- [ ] 直接 3D 选择或人工 ROI，记录 Keep/Remove/Protected 集合。
- [ ] 验证编辑器固定 commit 下的加载重排、选择读回和导出过滤；不能用数组位置冒充稳定身份。
- [ ] 删除、撤销、导出与重新加载；保存身份映射和固定相机对比。
- [ ] 工具无法提供可靠选择映射时保留独立 Python 操作路径；不让 GUI 编译阻塞官方实验。

### 输出与验收（M1）

SceneAsset、SelectionArtifact、删除后资产、映射及对比结果齐全。哈希不匹配或映射失效时拒绝应用；Remove 与 Protected 冲突必须先修正。重复应用同一选择能得到相同目标集合，撤销可恢复源资产。检查残留、误删和人工耗时。

此节点不承诺隐藏背景已修好。插值或伪监督修复另列为实验，不作为基础编辑验收前提。

## 阶段 2 · 官方修复基线与增强实验

### 目标

先独立验证官方流程与评测，再逐项开发增强。NativeBaseline 使用官方支持的场景、对象身份、mask 与人工核验目标，不依赖阶段 1 的选择产物。

### 输入与前置条件

固定 Inpaint360GS commit、环境、权重和配置，参考 [源码验证记录](06-verification.md)。准备官方兼容的图像、标定、checkpoint、对象特征和场景配置；只有 PLY 不自动满足这些条件。自有 paired GT 可并行采集，不阻塞公开样本。

### 实验步骤

| 实验 | 内容 | 定位 |
|---|---|---|
| B0 | 固定源 checkpoint 与实际删除集合，只删不补 | 删除对照 |
| B1 | 官方默认：虚拟视角数据准备、LaMa 补 RGB/深度、点云融合、Gaussian 优化；递归默认关闭 | 官方基线 |
| B2 | B1 + 有效真实背景观测优先恢复，检查目标排除、遮挡和深度可靠性 | 待开发增强 |
| B3 | B2 + 可靠背景冻结、受限优化/增删与必要过渡带 | 待开发增强 |

- [ ] 运行官方 `run_seg.sh` → `run_remove.sh` → `run_inpaint.sh`，记录实际删除集合（包含官方额外筛选）并以其构建 B0。
- [ ] 保存原始、B0、B1 三组模型和渲染。B2/B3 单独配置，不能写成官方已有能力。
- [ ] 分区已有可靠、已有受损、无有效观测和未知背景，记录观测/生成来源；增强方案按架构第七节验证。
- [ ] 基线稳定后再做 NBS、递归开关、背景优先恢复与冻结保护消融；改变删除集合的实验单独报告。

### 输出与验收（M2）

官方 B0/B1 可重复运行，实际删除集合可比较，数据依赖、产物、失败案例可追溯；下方统一协议与开发场景阈值冻结。M2 是官方基线节点，不代表 GSCleaner 外部选择链路已成功。

B2/B3 可在 M2 后继续深化，与阶段 3 交互分割并行。修复质量必须实测，不预设 SOTA、运行耗时或无观测区域大小。

## 阶段 3 · 可控三维分离与修复闭环

### 目标

将用户点击/框选转为可复核的 Gaussian 集合，并让 ExternalSelection 真正进入修复后端。这是 GSCleaner 的核心成功节点。

### 输入与前置条件

阶段 1 的身份协议和阶段 2 的已运行后端。FlashSplat 使用正确的闭式标签分配流程；SAGA 固定 v2 与预训练亲和特征，不能视为 PLY-only 即用分割器。

### 步骤

- [ ] 提示生成 target_mask_2d，比较 2D→3D 归属、多视角修正、Keep/Remove/Protected 和边界误删。
- [ ] GS-IoU 只关联已有 mask；标准 IoU 与代码度量分别校准阈值，冻结基线后比较。
- [ ] 按 [RemovalAdapter 契约](04-architecture.md#removaladapter选择到修复后端的适配契约)核验 checkpoint 身份、对象特征、相机、图像 mask 和配置依赖。
- [ ] ExternalSelection 在小场景逐步验证，保存转换清单；文件可读不等于后端可正确消费。
- [ ] 对同一用户确认删除集合比较仅删除和修复，保存 RecoveryArtifact 和保护范围。

### 输出与验收（M3）

用户选择 → 经核验的 3D 集合 → 后端适配 → 干净背景输出形成可重复闭环；在独立测试视角、冻结协议与对应质量门槛下，残留、误删、保护区保持度和修复表现通过验收。

有配准干净参考时可额外通过隐藏背景真实性验收；没有时仅能通过连续性、残留和保持度验收，真实性标记不可测。适配失败或修复超门槛退化均不算 M3 成功。

## 阶段 4 · 最小产品与分级交付

### 目标与步骤

连接编辑、mask 管理、修复、评测、撤销与导出；采用独立 Python 核心和已验证适配器，不先建设复杂调度框架或自研训练器。

- [ ] 校验 SceneAsset → SelectionArtifact → RecoveryArtifact → CleanSceneAsset 的身份和谱系。
- [ ] UI 按能力、监督来源及适配验证状态启用操作，解释不可用原因和质量证据。
- [ ] 导出 PLY、mask、映射、编辑历史、固定轨迹对比与质量/成本报告。

### 首版交付承诺（唯一维护表）

| 输入/能力 | 承诺 | 边界 |
|---|---|---|
| PLY-only | 选择、保护、删除、撤销、可视化与可追溯导出 | 修复有限或实验性，不承诺真实隐藏背景还原 |
| PLY + 配准原图/标定 | 经验证后端/适配器的有监督修复；局部保护按 B3 验收提供 | 校验格式、相机与训练器；文件存在不等于操作可行 |
| 仅原始图像 | 先经独立重建前置流程形成 SceneAsset，再进入编辑 | 不保证任意图像可重建，也不承诺首版自研训练器 |
| 有配准干净参考 | 对修复区域进行额外真实性定量评测 | 无参考时明确不可测 |

### 输出与验收（M4）

各能力对应的输入、编辑、修复（若支持）与导出流程通过测试；保护区限制、撤销和不可测状态显示正确。产品验收引用 M3 的修复证据，不用统一“修复成功”覆盖能力差异。

## 统一实验与验收协议

本节是阶段 2–4 唯一维护的评测协议；阶段章节只说明各自成功条件。

1. 冻结实验清单：源 checkpoint 哈希、用户目标及实际删除集合、优化/修复相机、独立测试相机、repair/protected 区域版本，以及代码、权重、配置和随机种子。
2. 测试影像不参与训练、伪监督或参数选择；审计初始 checkpoint 是否已经使用它们，泄漏时不能称为严格独立评测。无真实测试影像的虚拟轨迹只能用于连续性评审。
3. 保存原始、仅删除、删除并修复三组结果；增强分支另列。固定渲染器、分辨率、曝光、轨迹、指标脚本，以及 mask 极性、区域计算/置黑、裁剪和 padding。
4. 分别报告目标残留/背景误删（有标注时）、保护区保持度、修复区质量（有干净参考时）、边界与跨视角一致性，附耗时、显存和人工修正时间。
5. 保存固定轨迹视频与人工评审表，记录残留、误删、结构/纹理、边界、闪烁的通过/失败和原因；生成区域必须可识别。
6. 开发场景用于确定阈值、失败条件和 GPU 重复运行容限；随后冻结，在独立验收场景上判断。门槛未冻结时只算基线测量，不宣称工程验收通过。
7. 缺少配准干净参考时真实性为不可测，不能填零或自动判通过。虚拟视角效果不能证明真实还原；总体均值不能掩盖保护区退化。
8. 仅当所需指标达冻结门槛、保护区无超容限退化且身份/删除集合核验通过时，才判相应验收范围通过；保留失败和不可测项。

## 后续扩展（不编号）

- 自动候选/开放词汇排序：减少人工量，不自动决定对象是否该删除；低可见度只作不确定性。
- 无原图高质量修复：虚拟渲染与伪监督作为实验，记录真实观测缺失的限制。
- 阴影、反射、色溢：从局部处理到逆渲染，按业务质量要求独立验证。
- 碰撞几何：可靠深度与标定/尺度融合 TSDF、简化 mesh 或几何代理；Gaussian 中心不能直接视为表面。分别验证 USD 封装、GS 渲染与碰撞支持。
- 批量处理与 OperationPlan：流程稳定后再抽象。

## 待验证假设

不以“80% 只需前两层”“无观测区域通常很小”、固定成功率或算法优劣作为设计前提。实际统计人工 ROI 收益、无观测范围、递归补全效果、关联分数选择、冻结保护收益及简化 mesh 碰撞质量；各实验使用统一协议并记录适用条件。
