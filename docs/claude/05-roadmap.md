## 修订说明（2026-10-12）

本路线调整为四个研发阶段。五层模型仍作为问题分类，但首版不研发开放集合下的自动目标发现，也不要求先完成完整调度框架。

核心顺序是：先验证可控的人工编辑和身份协议，再验证背景修复，然后比较 2D→3D 归属方法，最后集成为最小产品。完整数据与 PLY-only 基础编辑可以并行；PLY-only 的高质量隐藏背景补全仍需单独标注证据边界。

| 阶段 | 内容 | 关键产出 |
|---|---|---|
| **阶段 1** | 数据与编辑基线 | 人工 Keep/Remove、稳定身份、删除导出、PLY-only 基础编辑 |
| **阶段 2** | Inpaint360GS 修复基线 | 同一删除集合下仅删除 vs 补全，背景分区与评测 |
| **阶段 3** | 可控三维对象分离 | 点击/框选 → 2D mask → 3D 集合，多视角修正 |
| **阶段 4** | GSCleaner 最小产品 | 编辑器、mask 管理、修复、评测和导出贯通 |

自动候选、阴影/反射清理、批处理和碰撞 mesh 是阶段 4 之后的扩展；不阻塞前四阶段。

## 阶段 1 · 数据与编辑基线

**目标**：先把资产身份、人工选择、删除、导出和对比渲染做成可重复实验。

- [ ] 公开场景 + 自有场景能力清单和源资产 SHA-256。
- [ ] 直接 3D 选择与 Keep/Remove/Protected 三类集合。
- [ ] PLY-only 可加载、虚拟相机渲染、人工选择、删除、导出；隐藏背景真实性暂不承诺。
- [ ] 删除前后多视角对比，记录残留、误删、索引映射和人工时间。
- [ ] 验证 SuperSplat/LichtFeld 是否能提供可消费的选择集合；工具能力未确认前保留独立 Python 路径。

**交付**：可重复运行的 Gaussian 删除、导出和编辑对比实验。


## 阶段 2 · Inpaint360GS 修复基线

**准备与评测协议**：固定官方 commit、环境、权重、参数和随机种子；预先划分优化与评测相机，评测相机不参与优化或伪监督。独立保存 `target_mask_2d`、`remove_mask_3d`、`repair_mask_2d` 和背景保护区域，固定 mask 极性、裁剪、padding、分辨率与指标实现。有配准干净参考时报告修复区域质量；没有时只报告残留、保持度和一致性，不把带干扰物 holdout 当作 GT。记录耗时、峰值显存和人工修正时间。自有 paired GT 并行采集，不阻塞公开样本。

**目标**：在**人工指定目标**的前提下，打通"删除 → 修复 → 评测"的完整链路。

**为什么这是第一主线**：人工目标减少候选生成的不确定性，但 2D→3D 归属和隐藏部分选择仍可能出错。先人工复核并冻结实际删除集合，再独立检查补全。

### 前置

固定官方 commit、环境、权重、参数和随机种子；先使用默认递归关闭配置。准备有干净参考的公开样本，自有 paired GT 并行采集。

Tier A：**原图 + 位姿 + 3DGS 可训练**。

### 实现

- [ ] **L0 Ingest**：能力探测 + 场景加载（[04-architecture.md](04-architecture.md) 第三节）
- [ ] **L1 Analyze（人工版）**：标注 `target_mask_2d` 或直接选择 3D 目标，生成并复核 `remove_mask_3d`；SuperSplat 选择需通过身份映射才能作为算法输入。
- [ ] **L2 Remove**：冻结删除集合，检查目标残留与受保护背景误删；产出带资产哈希/版本的 `mask.json`、编辑映射和 `repair_mask_2d`（见架构第六节）。
- [ ] **L3 Repair（官方基线）**：
  - [ ] NBS 判定：式 8 深度 + 虚拟相机圆周轨迹
  - [ ] 跨视角填充：原始背景像素需验证可见性、目标排除和深度可靠性；渲染来源单独标记
  - [ ] LaMa 补 RGB + 补深度
  - [ ] 深度反投影融合
  - [ ] 3DGS 微调（3D 混合监督，注意**全图 SSIM 不乘 mask**）
- [ ] **L5 Export**：导出干净 PLY + 质量报告

先复用官方训练和补全流程，用最小脚本保存配置、产物和质量报告；验证闭环后再扩展 `OperationPlan`，不自研训练器。

### 后续可选：几何选择基线

- [ ] RANSAC 地面平面 + 连通域 + 高度阈值 → 候选 blob
- [ ] 删除 + 空间插值
- [ ] 定位为后续选择模块对照；首轮修复实验用同一删除集合的“仅删除”作为必需对照，避免同时改变选择与补全。

### 验收（第一版的真正标准）

- [ ] 给定人工指定的目标，**一条命令**产出干净 PLY + mask.json + 质量报告
- [ ] **在未参与优化的相机轨迹上，背景保持连续**
- [ ] 固定版本、配置和随机种子；记录 GPU 非确定性，对重复运行采用预先约定的误差容限，不要求逐位相同。
- [ ] 与同一删除集合的“仅删除”对比；有干净参考时测修复区域质量，并独立报告未编辑区域保持度、残留、人工评审与资源成本。

### 关键失败模式与定位

| 现象 | 可能原因 |
|---|---|
| 残留浮空碎雾 | 2D→3D 归属错误、隐藏部分漏选、身份映射错误或 densify 策略 |
| 背景误删或被改坏 | 删除集合越界、保护区域缺失或补全优化影响范围过大 |
| 修补区域糊 | NBS 判定过宽 / LaMa 输入 mask 不当 |
| 跨视角不一致 | 缺虚拟视角 / 条件 inpainting 未开 |
| 边界断裂 | 3D 混合监督缺失或权重不当 |

## 阶段 3 · 可控三维对象分离

**目标**：把"人工指定目标"升级为"半自动关联"。

### 实现

- [ ] **GS-IoU 关联机制**（[03-inpaint360gs.md](03-inpaint360gs.md) 机制 1）：
  - [ ] **实现两种度量**：论文式 2（标准 IoU）与代码的 `IOU_heighlight`（覆盖率的非线性变换）
  - [ ] 将图像分为 16×16 网格单元（不是每块 16×16 像素）+ 每单元 KMeans 深度二分 + 最近 30% 截断；记录小单元整数截断导致空种子的情况
  - [ ] Key Object Database + 阈值关联
- [ ] 在冻结基线上对比两种度量；分别校准阈值，不直接共用数值。代码分数 s=r/(1+r)，其中 r 是当前集合覆盖率，s=0.1 对应 r≈11.1%。
- [ ] 先以 FlashSplat 做 2D→3D 基线；SAGA 仅在有完整训练数据和预训练 3D 特征的场景验证，不把它当作 PLY-only 即用组件。

> **注意**：GS-IoU 是**关联器不是检测器**（[03-inpaint360gs.md](03-inpaint360gs.md) 价值 1）。本阶段仍然需要人工给出初始目标，只是把"逐视角手工"变成"给一次，自动关联到全视角"。

### 产出

- 给定一个 2D mask，自动关联到 3D 全视角一致
- 关联精度对比（vs 人工标注 IoU）

## 阶段 2B · 修复质量深化

**目标**：从"能删干净"提升到"修得好"。

### 实现

- [ ] NBS 精确判定优化（式 8 深度 + 虚拟轨迹，[03-inpaint360gs.md](03-inpaint360gs.md) 机制 3）
- [ ] 遮挡物临时移除 / 恢复流程（需 YOLOv8）
- [ ] **递归 vs 独立 inpainting 消融实验**（代码默认关闭 `--recursive_guide`，需自己验证增益）
- [ ] inpaint 区域缩小比例报告（3DGIC 报告 30–60% 可作参照）
- [ ] 评估是否上扩散模型——**基准证据显示重建式 inpainter 在 3D 一致性上常胜过扩散模型**（[01-landscape.md](01-landscape.md) 第 3.3 节）

### 产出

- 修复质量达到可比 SOTA 水平
- **inpaint 区域缩小比例**的量化数据

### 参照算力

- 3DGIC：单场景 5000 步，**RTX 3090 约 15 分钟** → 4090 可行
- Inpaint360GS：训练 12–21.5 分钟 + inpaint 2.5–3 分钟，**总 24 / 15 分钟**

## 阶段 4 · GSCleaner 最小产品

**目标**：把已验证的编辑与修复连接为一个可检查、可回退的工作流。

- [ ] 加载 PLY/完整数据、列出能力清单和真实/伪监督来源。
- [ ] 点击、框选或直接 3D 选择，复核 Keep/Remove/Protected 集合与身份映射。
- [ ] 保存并校验 mask 的资产哈希、版本；撤销或重跑不复用失效索引。
- [ ] 调用修复后端，显示背景分区、未知区域和生成区域。
- [ ] 输出 PLY、mask、映射、固定相机对比和质量/成本报告。
- [ ] 验证可靠区域冻结、局部优化范围和边界过渡；同时检查未编辑区域渲染变化。

**交付**：从输入、人工选目标、复核、删除、修复到导出的完整流程。暂不实现复杂调度框架、自研训练器或自动目标发现。阶段 1 与阶段 2 可以并行，阶段 3 为两条线提供更易用的选择接口。

## 阶段 4B · 自动候选（后续扩展）

**目标**：减少人工介入。

### 实现

- [ ] 开放词汇语义（CLIP / VLM）作为**排序信号**
- [ ] 几何 + 观测一致性作为**候选生成**（[04-architecture.md](04-architecture.md) 第五节）
- [ ] 候选排序 + 人工确认界面（mask-first 产物）

### ⚠ 必须接受的边界

见 [00-requirements.md](00-requirements.md) 第四节约束 1：

> **开放集合下不存在完整的自动解决方案。** "不该在"是语用判断，不是视觉属性。
>
> 本阶段的目标是**减少人工介入量**，不是**消除人工**。

**低可见度只能作为不确定性分数，不能作为删除证据**（[04-architecture.md](04-architecture.md) 第五节更正）——否则会误删背景。

### 产出

- 候选生成 + 排序 + 确认的工作流
- 各条信号路线的召回率统计

## 阶段 5+ · 阴影 / 重光照 / 碰撞 Mesh（后续扩展）

**目标**：仿真可用性。

**注意**：**这是唯一"没人替你解决"的洞。** Inpaint360GS 作者明确把它列为 future work（"residual shadow artifacts cast by the removed objects"）。因此**独立成线**，不阻塞主线。

### 实现（务实版优先）

- [ ] 地面平面提取
- [ ] 地面暗斑检测 + 局部颜色归一化压平
- [ ] 反射残留处理（若地面反光）
- [ ] 色溢处理
- [ ] **碰撞 mesh**：用可靠渲染深度与已知相机做 TSDF 融合，再用 Marching Cubes 提取并简化 mesh（需尺度校准；不能直接把 Gaussian 中心当作表面或 TSDF），或退化为 AABB / 凸包
- [ ] 一致性校验：GS 视觉几何与碰撞 mesh 对齐
- [ ] 分别验证 USD 资产封装、GS 渲染插件支持和碰撞 mesh 导入；导出 USD 不代表 Isaac Sim 原生支持 GS 渲染或碰撞。

### 评估

- [ ] 消融：有/无阴影清理，在**"新物体放入场景"**下的视觉一致性差异

> **这才是评审者真正会看的指标** —— 单纯看删除后的渲染，有无阴影的区别常常不明显；但把新物体放进去，阴影不随新光源变化就立刻穿帮。

### 逆渲染路线（第二阶段选项）

仅在 [README.md](README.md) 待决问题第 4 条的答案为"需要光照自洽"时才考虑：

- **GS-ID**：per-splat 可见性向量解耦阴影 + 环境贴图 + 各向异性球面高斯 + 扩散先验
- **ComGS**：Surface Octahedral Probes，八角图存光照与遮挡；约 28 FPS，单次编辑约 36 秒

**投入对比**：完整逆渲染与务实压平的投入**差 5–10 倍**。

### 调研缺口

> **未找到以"接触阴影清除"命名的任务定义。** 可能需要自己定义这个子问题。

## 阶段 1B · PLY-only 基础编辑（与阶段 1 并行）

**目标**：覆盖只有 PLY 的输入。

**为什么与阶段 1 并行**：基础编辑无需真实监督，可快速验证加载、选择、身份映射、删除和导出；隐藏背景真实性与高质量补全仍需单独实验。实际 PLY-only 资产仍可评估残留、保持度和多视角一致性。

### 实现

- [ ] 人工 ROI 指定（`C+` 形态，见 [00-requirements.md](00-requirements.md) 第五节）
- [ ] 几何 + 观测一致性候选（若能力允许）
- [ ] 空间插值修复作为基础路径；若可渲染且训练器兼容，单独评估虚拟视角分割、生成补全与伪监督微调。
- [ ] 明确的质量等级标注与降级警告

### 额外硬限制

> **单份静态 PLY 不能可靠恢复运动历史；可人工选择疑似动态残留，但不能把外观异常直接判为动态物体。**
>
> 若采集流程可控，最优解是采集阶段清场重拍，而非事后补救。

### 产出

- 降级交付能力 + 明确的质量标注

## 待验证假设清单

| # | 假设 | 验证方式 | 关联阶段 |

## 立即可做的三件事

1. 选择一个有干净参考的公开场景和一个自有完整数据场景，记录输入能力。
2. 固定官方 commit 与默认配置，复核删除集合，对比仅删除与默认补全。
3. 保存固定评测视角、mask、保持度与修复质量报告，并记录显存、耗时和人工修正时间；自有 paired GT 并行采集。
