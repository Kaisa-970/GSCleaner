## 修订说明（2026-10-12）

本路线图经过一次重排，原因是源码验证发现：

**原方案先做 PLY-only 几何 baseline，再逐步走向完整方案。问题在于：PLY-only 没有真实背景监督，容易得到一个"能跑、但无法证明有效"的结果。**

新方案的核心原则：

> **先验证「给定正确目标，能不能产出干净背景」，再验证「能不能自动找到目标」。**
>
> 否则**识别失败和补全失败会混在一起，无法判断问题出在哪里。**

这也是本路线图最重要的一条方法论——**先建立纵向闭环，再横向扩展能力**。

### 与旧版的差异

| 项 | 旧版 | 新版 |
|---|---|---|
| 第一主线 | PLY-only 几何启发式 baseline | **Tier A 人工指定目标的完整纵向闭环** |
| 几何基线 | 主路径 | **降为内部对照点**（见下） |
| 自动候选生成 | Phase 2（较早） | **Phase 4（推后）** |
| PLY-only | Phase 1 | **Phase 6（推后）** |

### 关于几何基线的保留

旧版让 Phase 1 先做几何启发式，理由不是"它能交付"，而是**它给定点**——没有这个对照，无法判断 Phase 2 的 2D lifting 是真的在起作用还是碰巧。

**这个理由仍然成立**，所以保留它，但**降为内部对照点**：

- 几十行代码，不做成交付形态
- 明确承认它**不产出可交付结论**
- 作用仅是提供"不做自动化的下界"

**两条并行**：一条证明"能修好"（Tier A 闭环），一条提供"下界"（几何基线）。

## 总览

| 阶段 | 内容 | 关键产出 |
|---|---|---|
| **Phase 0** | 最小样本 + 官方默认基线 + 评测协议 | 首轮实验可启动 |
| **Phase 1** | **Tier A 完整纵向闭环**（人工目标 mask） | 端到端可跑 + 可复现数字 |
| **Phase 2** | 多视角 mask 关联与对象删除 | 关联机制可用 |
| **Phase 3** | NBS 判定 + 背景投影 + LaMa 补全 + 3D 优化 | 修复质量提升 |
| **Phase 4** | 自动候选生成与开放词汇排序 | 减少人工介入 |
| **Phase 5** | 阴影 / 重光照 / 碰撞 mesh（独立产品线） | 仿真可用 |
| **Phase 6** | PLY-only 人工 ROI 与可选渲染伪监督 | 分级交付与真实性边界 |

**第一版应证明的只有一件事**：

> **在有原图和相机位姿的场景中，用户指定一个目标后，系统能稳定删除它，并在未参与优化的相机轨迹上保持背景连续。**

**第一版不应同时纳入**：PLY-only、自动候选枚举、阴影清理、碰撞 mesh。

## Phase 0 · 最小实验准备

**目标**：准备能运行首轮官方基线的输入和评测协议。工具适配、全部论文数字和所有不确定项不作为开工前置条件。

### 0.1 样本与能力

- [ ] 选择一个有配准干净参考的公开场景，确认官方训练、删除、补全所需输入齐全。
- [ ] 选择一个自己的完整数据场景，记录原图、标定、Gaussian 格式、训练器兼容性和已有对象特征。
- [ ] 探测 `renderable`、`segmentable`、`source_supervised`、`retrainable`、`has_holdout`、`has_clean_reference`、`has_source_cameras`、`has_virtual_cameras`、`has_metric_scale`、`relightable`、`has_object_features`。
- [ ] 没有自有样本时先运行公开场景，并将业务适用性标为待验证。

原始相机不是渲染的必要条件；真实监督、留出视角和干净参考分别记录，不互相替代。

### 0.2 冻结官方基线

- [ ] 固定 Inpaint360GS commit（见 [06-verification.md](06-verification.md)）、环境、权重、参数和随机种子。
- [ ] 跑通 `run_seg.sh` → `run_remove.sh` → `run_inpaint.sh`，首次使用官方代码默认配置，递归补全关闭。
- [ ] 保存原始资产、删除集合、相机列表、渲染结果和执行日志。
- [ ] 记录官方与论文的差异；完整论文指标复现作为后续任务，不阻塞首轮闭环。

GS-IoU 度量对比放到 Phase 2，递归补全消融放到 Phase 3。先建立可比较基线，再改变单个变量。

### 0.3 评测协议

- [ ] 预先划分优化与评测相机；评测相机不参与优化或伪监督生成，避免信息泄漏。
- [ ] 独立保存目标 2D mask、删除 3D mask、修复 2D mask 与背景保护区域。
- [ ] 固定 mask 极性、裁剪、padding、分辨率和指标实现；区分区域计算与将非目标区域置黑后全图计算。
- [ ] 以同一删除集合对比“仅删除”和“官方默认补全”，分别检查残留、补全区域、未编辑背景与多视角连续性。
- [ ] 记录耗时、峰值显存、人工选择/修正时间，保留固定轨迹的人工评审视频。
- [ ] 有配准干净参考时报告修复区域 PSNR/SSIM/LPIPS；没有时标记该项不可测，不以带干扰物的 holdout 冒充 GT。

**自有 paired GT 采集并行推进**：尽量固定轨迹、曝光、白平衡与照明；清场前后仍需校验配准误差。它不阻塞公开样本的首轮实验。

### 0.4 可选工具验证（不阻塞主线）

- [ ] 需要时验证 LichtFeld 编译、headless Python API、选择/删除/导出与相机读取。
- [ ] SuperSplat 首轮用于预览与复核；作为标注器前验证重排、过滤、删除、导出的身份映射。
- [ ] 关闭重排和未压缩导出只能作为实验条件，不能替代资产哈希与索引映射。

### 产出与退出条件

一个公开场景的官方流程可运行，样本能力表、固定评测协议与实验配置可追溯，即可进入 Phase 1。自有场景缺失不阻止公开复现，但阻止业务适用性结论。

LichtFeld 编译失败不阻塞原型；缺少干净参考时继续检查保持度、残留和一致性，不声称已验证隐藏背景真实性。

## Phase 1 · Tier A 完整纵向闭环（核心阶段）

**目标**：在**人工指定目标**的前提下，打通"删除 → 修复 → 评测"的完整链路。

**为什么这是第一主线**：人工目标减少候选生成的不确定性，但 2D→3D 归属和隐藏部分选择仍可能出错。先人工复核并冻结实际删除集合，再独立检查补全。

### 前置

Tier A：**原图 + 位姿 + 3DGS 可训练**。

### 实现

- [ ] **L0 Ingest**：能力探测 + 场景加载（[04-architecture.md](04-architecture.md) 第三节）
- [ ] **L1 Analyze（人工版）**：标注 `target_mask_2d` 或直接选择 3D 目标，生成并复核 `remove_mask_3d`；SuperSplat 选择需通过身份映射才能作为算法输入。
- [ ] **L2 Remove**：冻结删除集合，检查目标残留与受保护背景误删；产出带资产哈希/版本的 `mask.json`、编辑映射和 `repair_mask_2d`（见架构第六节）。
- [ ] **L3 Repair（完整版）**：
  - [ ] NBS 判定：式 8 深度 + 虚拟相机圆周轨迹
  - [ ] 跨视角填充真观测（**先做这一步，它们是真观测不是幻觉**）
  - [ ] LaMa 补 RGB + 补深度
  - [ ] 深度反投影融合
  - [ ] 3DGS 微调（3D 混合监督，注意**全图 SSIM 不乘 mask**）
- [ ] **L5 Export**：导出干净 PLY + 质量报告

先复用官方训练和补全流程，用最小脚本保存配置、产物和质量报告；验证闭环后再扩展 `OperationPlan`，不自研训练器。

### 后续可选：几何选择基线

- [ ] RANSAC 地面平面 + 连通域 + 高度阈值 → 候选 blob
- [ ] 删除 + 空间插值
- [ ] 定位为后续选择模块对照；首轮修复实验用同一删除集合的“仅删除”作为必需对照，避免同时改变选择与补全。

### 验收（第一版的真正标准）

- [ ] 给定人工指定的目标，**一条命令**产出干净 PLY + mask.json + 质量报告
- [ ] **在未参与优化的相机轨迹上，背景保持连续**
- [ ] 固定版本、配置和随机种子；记录 GPU 非确定性，对重复运行采用预先约定的误差容限，不要求逐位相同。
- [ ] 与同一删除集合的“仅删除”对比；有干净参考时测修复区域质量，并独立报告未编辑区域保持度、残留、人工评审与资源成本。

### 关键失败模式与定位

| 现象 | 可能原因 |
|---|---|
| 残留浮空碎雾 | 2D→3D 归属错误、隐藏部分漏选、身份映射错误或 densify 策略 |
| 背景误删或被改坏 | 删除集合越界、保护区域缺失或补全优化影响范围过大 |
| 修补区域糊 | NBS 判定过宽 / LaMa 输入 mask 不当 |
| 跨视角不一致 | 缺虚拟视角 / 条件 inpainting 未开 |
| 边界断裂 | 3D 混合监督缺失或权重不当 |

## Phase 2 · 多视角 Mask 关联与对象删除

**目标**：把"人工指定目标"升级为"半自动关联"。

### 实现

- [ ] **GS-IoU 关联机制**（[03-inpaint360gs.md](03-inpaint360gs.md) 机制 1）：
  - [ ] **实现两种度量**：论文式 2（标准 IoU）与代码的 `IOU_heighlight`（覆盖率的非线性变换）
  - [ ] 将图像分为 16×16 网格单元（不是每块 16×16 像素）+ 每单元 KMeans 深度二分 + 最近 30% 截断；记录小单元整数截断导致空种子的情况
  - [ ] Key Object Database + 阈值关联
- [ ] 在冻结基线上对比两种度量；分别校准阈值，不直接共用数值。代码分数 s=r/(1+r)，其中 r 是当前集合覆盖率，s=0.1 对应 r≈11.1%。
- [ ] 接入 FlashSplat 或 SAGA 做 mask lifting（[01-landscape.md](01-landscape.md) 第 2 节）

> **注意**：GS-IoU 是**关联器不是检测器**（[03-inpaint360gs.md](03-inpaint360gs.md) 价值 1）。本阶段仍然需要人工给出初始目标，只是把"逐视角手工"变成"给一次，自动关联到全视角"。

### 产出

- 给定一个 2D mask，自动关联到 3D 全视角一致
- 关联精度对比（vs 人工标注 IoU）

## Phase 3 · NBS 判定与修复质量优化

**目标**：从"能删干净"提升到"修得好"。

### 实现

- [ ] NBS 精确判定优化（式 8 深度 + 虚拟轨迹，[03-inpaint360gs.md](03-inpaint360gs.md) 机制 3）
- [ ] 遮挡物临时移除 / 恢复流程（需 YOLOv8）
- [ ] **递归 vs 独立 inpainting 消融实验**（代码默认关闭 `--recursive_guide`，需自己验证增益）
- [ ] inpaint 区域缩小比例报告（3DGIC 报告 30–60% 可作参照）
- [ ] 评估是否上扩散模型——**基准证据显示重建式 inpainter 在 3D 一致性上常胜过扩散模型**（[01-landscape.md](01-landscape.md) 第 3.3 节）

### 产出

- 修复质量达到可比 SOTA 水平
- **inpaint 区域缩小比例**的量化数据

### 参照算力

- 3DGIC：单场景 5000 步，**RTX 3090 约 15 分钟** → 4090 可行
- Inpaint360GS：训练 12–21.5 分钟 + inpaint 2.5–3 分钟，**总 24 / 15 分钟**

## Phase 4 · 自动候选生成与开放词汇排序

**目标**：减少人工介入。

### 实现

- [ ] 开放词汇语义（CLIP / VLM）作为**排序信号**
- [ ] 几何 + 观测一致性作为**候选生成**（[04-architecture.md](04-architecture.md) 第五节）
- [ ] 候选排序 + 人工确认界面（mask-first 产物）

### ⚠ 必须接受的边界

见 [00-requirements.md](00-requirements.md) 第四节约束 1：

> **开放集合下不存在完整的自动解决方案。** "不该在"是语用判断，不是视觉属性。
>
> 本阶段的目标是**减少人工介入量**，不是**消除人工**。

**低可见度只能作为不确定性分数，不能作为删除证据**（[04-architecture.md](04-architecture.md) 第五节更正）——否则会误删背景。

### 产出

- 候选生成 + 排序 + 确认的工作流
- 各条信号路线的召回率统计

## Phase 5 · 阴影 / 重光照 / 碰撞 Mesh（独立产品线）

**目标**：仿真可用性。

**注意**：**这是唯一"没人替你解决"的洞。** Inpaint360GS 作者明确把它列为 future work（"residual shadow artifacts cast by the removed objects"）。因此**独立成线**，不阻塞主线。

### 实现（务实版优先）

- [ ] 地面平面提取
- [ ] 地面暗斑检测 + 局部颜色归一化压平
- [ ] 反射残留处理（若地面反光）
- [ ] 色溢处理
- [ ] **碰撞 mesh**：用可靠渲染深度与已知相机做 TSDF 融合，再用 Marching Cubes 提取并简化 mesh（需尺度校准；不能直接把 Gaussian 中心当作表面或 TSDF），或退化为 AABB / 凸包
- [ ] 一致性校验：GS 视觉几何与碰撞 mesh 对齐
- [ ] 分别验证 USD 资产封装、GS 渲染插件支持和碰撞 mesh 导入；导出 USD 不代表 Isaac Sim 原生支持 GS 渲染或碰撞。

### 评估

- [ ] 消融：有/无阴影清理，在**"新物体放入场景"**下的视觉一致性差异

> **这才是评审者真正会看的指标** —— 单纯看删除后的渲染，有无阴影的区别常常不明显；但把新物体放进去，阴影不随新光源变化就立刻穿帮。

### 逆渲染路线（第二阶段选项）

仅在 [README.md](README.md) 待决问题第 4 条的答案为"需要光照自洽"时才考虑：

- **GS-ID**：per-splat 可见性向量解耦阴影 + 环境贴图 + 各向异性球面高斯 + 扩散先验
- **ComGS**：Surface Octahedral Probes，八角图存光照与遮挡；约 28 FPS，单次编辑约 36 秒

**投入对比**：完整逆渲染与务实压平的投入**差 5–10 倍**。

### 调研缺口

> **未找到以"接触阴影清除"命名的任务定义。** 可能需要自己定义这个子问题。

## Phase 6 · PLY-only 人工 ROI 删除与几何降级模式

**目标**：覆盖只有 PLY 的输入。

**为什么推到后期**：缺少真实影像时，隐藏背景真实性难以验证。先在完整数据上验证主线，再剥离原图/标定进行 PLY-only 实验，可利用保留的干净参考衡量退化。实际 PLY-only 资产仍可评估残留、保持度和多视角一致性。

### 实现

- [ ] 人工 ROI 指定（`C+` 形态，见 [00-requirements.md](00-requirements.md) 第五节）
- [ ] 几何 + 观测一致性候选（若能力允许）
- [ ] 空间插值修复作为基础路径；若可渲染且训练器兼容，单独评估虚拟视角分割、生成补全与伪监督微调。
- [ ] 明确的质量等级标注与降级警告

### 额外硬限制

> **单份静态 PLY 不能可靠恢复运动历史；可人工选择疑似动态残留，但不能把外观异常直接判为动态物体。**
>
> 若采集流程可控，最优解是采集阶段清场重拍，而非事后补救。

### 产出

- 降级交付能力 + 明确的质量标注
